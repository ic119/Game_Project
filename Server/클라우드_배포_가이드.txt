서버/DB 무료 클라우드 배포 가이드
====================================

[현재 상태]
- Server/MainServer/docker-compose.yml에 MySQL + MainServer(HTTP) + Caddy(TLS 종료) +
  GameServer(TCP, 자체 TLS)가 이미 하나로 묶여 있음. 별도 코드 수정 없이 그대로 클라우드에 올릴 수 있는 상태.
- MainServer: HTTP API 서버 (로그인/회원가입/캐릭터 CRUD). 컨테이너 내부 8080에서만 열리고
  호스트에 직접 노출되지 않는다 - 외부에서는 반드시 Caddy(443)를 거쳐야 한다.
- Caddy: MainServer 앞단 리버스 프록시 + TLS 종료. DOMAIN을 .env에 설정하면 Let's Encrypt
  인증서를 자동 발급/갱신한다(포트 80/443).
- GameServer: 순수 TCP 소켓 서버(실시간 이동/채팅/전투), 포트 9000. HTTP를 거치지 않으므로
  Caddy가 아니라 자체적으로 SslStream 기반 TLS를 적용한다(GameServerCertificateProvider.cs).
  실제 인증서를 지정하지 않으면 자체 서명 인증서를 자동 생성하는데, 이 경우 클라이언트
  프로덕션(Release) 빌드는 접속을 거부한다(UNITY_EDITOR/DEVELOPMENT_BUILD만 자체 서명을 신뢰) -
  정식 배포 전 아래 [GameServer 인증서] 절차를 반드시 거칠 것.
- MySQL: docker-compose 내부 backend 네트워크에만 연결되어 있어 기본적으로
  외부에 노출되지 않음 (안전한 상태, 유지할 것)


[핵심 제약사항]
GameServer는 HTTP가 아니라 순수 TCP 소켓 서버다. Render, Railway, Vercel 같은
"HTTP 앱 전용" 무료 PaaS는 TCP 포트를 외부에 그대로 열어주지 않는 경우가 많아
GameServer가 정상 동작하지 않을 수 있다. 따라서 TCP 포트를 자유롭게 열 수 있는
플랫폼(VM형 서비스)을 선택해야 한다.


[추천 플랫폼: Oracle Cloud "Always Free" VM]
가입 절차가 다소 까다롭지만(카드 등록 필요), 기간 제한 없이 영구 무료이며
리눅스 VM에 root 권한이 그대로 주어져서 기존 docker-compose.yml을 코드 수정 없이
그대로 올릴 수 있다. 가장 마찰이 적은 선택.

배포 절차:
1. VM 생성
   - Oracle Cloud 콘솔에서 Always Free 대상 인스턴스(Ampere A1 또는 Micro) 생성
   - OS는 Ubuntu 선택

2. Docker 설치
   curl -fsSL https://get.docker.com | sh
   (docker compose plugin도 함께 설치됨)

3. 코드 업로드
   - VM에서 git clone으로 레포를 받거나 Server/ 폴더만 scp로 전송

4. .env 설정
   - .env.example을 .env로 복사
   - MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD, JWT_KEY 값을 채움
   - DOMAIN을 채우면 Caddy가 그 도메인으로 HTTPS를 자동 발급한다 - 채우기 전에 그 도메인의
     DNS A 레코드가 이 VM의 공인 IP를 가리키도록 먼저 설정해둘 것. 아직 도메인이 없다면
     DOMAIN을 비워두고 넘어가도 mysql/mainserver/gameserver는 정상 기동한다(caddy 컨테이너만
     재시작 루프에 빠짐 - 도메인이 생기면 채우고 docker compose up -d --build만 다시 실행).
   - .env는 .gitignore로 커밋에서 제외되어 있으니 비밀값을 여기에만 적을 것

5. 실행
   docker compose up -d --build

6. 방화벽 오픈
   - Oracle Cloud 콘솔의 Security List(또는 VM 내 ufw)에서
     80/443(Caddy, HTTPS), 9000(GameServer TCP) 인바운드 허용
   - 8080은 열지 않는다 - mainserver는 호스트에 노출되지 않고 Caddy를 통해서만 접근 가능하다
   - 3306(MySQL)은 절대 외부에 열지 말 것
     (현재 compose 구조상 mysql은 backend 내부 네트워크에만 있어 기본적으로 안전함)


[GameServer 인증서 (정식 배포 전 필수)]
GameServer는 HTTP가 아니라 순수 TCP라 Caddy가 대신 TLS를 처리해줄 수 없다 - 자체적으로
SslStream을 쓴다(GameServerCertificateProvider.cs). DOMAIN을 설정하지 않았거나
GAMESERVER_TLS_CERT_PATH를 비워두면 서버가 자체 서명 인증서를 자동 생성해 쓰는데,
클라이언트 Release 빌드는 이 인증서를 신뢰하지 않도록 만들어져 있어(치트용 서버 스푸핑 방지와
같은 이유) 정식 배포 전에는 실제 인증서를 지정해야 한다.

가장 쉬운 방법 - Caddy가 이미 발급받은 인증서를 재사용:
1. Caddy가 인증서를 저장하는 경로를 확인(볼륨 caddy_data 내부,
   대략 /data/caddy/certificates/acme-v02.api.letsencrypt.org-directory/<도메인>/)
2. 그 안의 <도메인>.crt(체인 포함)와 <도메인>.key를 PFX로 변환:
   openssl pkcs12 -export -out gameserver.pfx -inkey <도메인>.key -in <도메인>.crt -passout pass:원하는비밀번호
3. 변환한 gameserver.pfx를 Server/MainServer/certs/ 아래로 복사(.gitignore로 커밋 제외됨)
4. .env에 GAMESERVER_TLS_CERT_PATH=/certs/gameserver.pfx, GAMESERVER_TLS_CERT_PASSWORD=위에서 정한 비밀번호 채움
5. docker compose up -d --build 재실행

인증서는 90일마다 Caddy가 자동 갱신하지만 GameServer는 시작 시 한 번만 읽으므로, 갱신될 때마다
위 2~5번을 반복하거나(수동), cron으로 자동화해야 한다 - 아직은 수동 갱신을 전제로 한다.


[클라이언트(Unity) 쪽에서 바꿀 것]
서버 주소는 SerializeField로 인스펙터에 노출되어 있어 코드 수정 없이
값만 바꾸면 된다.

- ServerConnectManager.serverBaseUrl
  현재값: https://localhost:58208 (로컬 개발용 HTTPS)
  아래로 변경(Caddy가 발급한 도메인 기준, 포트 생략 - 443 기본값):
  https://<DOMAIN>

- GameServerConnectManager.host / port
  host: <DOMAIN>  (GameServer 인증서를 그 도메인 이름으로 발급했다면 IP가 아니라 도메인으로 접속해야
                    TLS 인증서 검증(호스트명 일치)을 통과한다)
  port: 9000

값을 바꾼 뒤 다른 PC에서 접속하려면 클라이언트를 다시 빌드(exe)해야 한다.
에디터 플레이 모드 테스트만 할 경우 인스펙터 값 수정으로 충분하다 - 단, 에디터/DEVELOPMENT_BUILD는
자체 서명 인증서도 무조건 신뢰하므로 [GameServer 인증서] 절차 없이 VM IP로 바로 테스트할 수 있다.


[보안 관련 참고사항]
- MainServer(로그인 등)는 이제 Caddy가 Let's Encrypt HTTPS를 자동으로 씌운다(DOMAIN 설정 시).
  DOMAIN을 비워둔 채로는 여전히 평문 HTTP이므로, 로그인 자격증명을 실제로 주고받기 전에는
  반드시 도메인을 연결할 것.
- GameServer TCP도 이제 SslStream으로 암호화된다. 다만 자체 서명 인증서(기본값)는 사실상
  "누구나 만들 수 있는 인증서"라 도청은 막아도 서버 신원 위조까지 막지는 못한다 - 정식 서비스라면
  위 [GameServer 인증서] 절차로 반드시 실제 인증서를 지정할 것.


[대안: Fly.io]
Oracle Cloud 가입이 번거로울 경우의 차선책.
무료 크레딧 한도 내에서 fly.toml에 TCP 서비스 정의가 가능해 GameServer도
띄울 수 있다. 다만 설정 파일을 새로 작성해야 하고, 무료 한도가 Oracle보다
빡빡한 편이다.
