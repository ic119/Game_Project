- 커밋 이력 약 530개 (작업 과정이 보임)

  (던전 데이터는 있으나 플레이 가능한 연결 여부 확인 필요)
- 클라이언트 자동 테스트 0개, MainServer 테스트 0개
- CI 없음, 시퀀스 다이어그램 부족, 부하/성능 수치 없음

2. 제출 전 반드시 해결할 문제 3가지
---------------------------------------------------------------

(1) DB 비밀번호가 커밋되어 있음  [미해결]
    - Server/MainServer/MainServer/appsettings.json 의 ConnectionStrings에 개발용 DB 비밀번호가 들어 있음
    - 과거 커밋 f5495dcd (Docker 구성 추가)부터 이력에도 남아 있음
    - README는 "저장소에 채워 두지 않았다"고 쓰여 있어 실제와 다름
    - 조치: 설정을 appsettings.Development.json(gitignore) / 환경변수 / user-secrets 로 분리,
      사용 중인 DB 비밀번호 변경, README 설명 정정
    - 이력에서 지우려면 git filter-repo --replace-text 가 필요 (아래 4장 참고)

(2) 저장소 크기  [일부 해결]
    - 2026-10-07 기준 .git 팩 약 1.33GB, HEAD 추적 파일 합계 약 1.8GB
    - 이미 한 일: 커밋 441e6b35
        · 미사용 폰트 SDF 3개 삭제 (LiberationSans / Maplestory Bold / Pretendard-Black, 약 102MB)
        · 서드파티/VFX 데모 씬 59개 + RPG Tiny Fantasy World의 Manual 이미지 삭제 (약 80MB)
    - 그러나 과거 커밋의 객체는 그대로이므로 .git 크기는 줄지 않았음
      (실제로 줄이려면 히스토리 재작성 필요, 또는 아래 4장의 "공개용 저장소 분리")
    - 남은 큰 항목:
        · @ThirdParty/RPGTinyHeroWorldBundlePBR  약 681MB -> 데모 씬/매뉴얼 제거 후에도 큼
        · @ThirdParty/RPGMonsterBundlePBR        약 376MB
        · Resources/Fonts 의 사용 중인 SDF 5개   약 180MB (각 32~38MB, 텍스트 YAML)
        · Lana Studio 약 110MB, VFX_Klaus 73MB, Suriyun 72MB, LowPolyAssetBundle 51MB
        · Floor001.prefab 약 42MB (안 쓰는 구역/나무 제거로 런타임 최적화 + 약 절반 감소 기대.
          단, 서버 데이터와 연결된 마커/NavGrid 기준 영역은 지우면 안 됨.

(3) 서드파티 에셋 재배포 문제  [미해결]

    - 파일을 지워도 과거 커밋에서 내려받을 수 있음

4. 추천안: 하이브리드 (원본 보존 + 공개용 저장소 파생)
---------------------------------------------------------------
핵심 아이디어: 원본은 그대로 두고 "공개용 저장소"를 별도로 만든다. 원본을 force push 하지 않는다.

  기존 Game_Project            -> 비공개로 전환 (전체: 에셋, 전 이력 보존)
  새 공개용 저장소(이름 예시: Game_Project-Portfolio)
                                -> Server/ 전체 + Client/Assets/@Scripts + 에디터 툴 + 문서
                                   (README, 각종 가이드 txt)

장점
- 원본 이력/해시가 그대로 보존되어 되돌릴 위험이 없음
- 서버/클라이언트 스크립트는 서드파티 에셋에 의존하지 않아 라이선스 문제 없이 공개 가능
- 커밋 이력, 테스트 약 193개, CI를 공개 상태로 보여줄 수 있음
- 파생 과정에서 --replace-text 로 과거 커밋의 DB 비밀번호를 치환 가능
- 에셋이 빠져 크기가 크게 줄어듦 (예상: 수십 MB 수준, 만들어 본 뒤 측정 필요)

한계
- 공개 저장소만으로는 Unity 프로젝트가 열리지 않음
  -> README에 "클라이언트는 에셋 의존으로 비공개, 플레이 영상으로 대체"를 명시하고 영상 첨부

비교
                     비공개+발췌   하이브리드(추천)   히스토리 재작성 후 공개(A)
  원본 보존           높음         높음               낮음 (force push)
  평가자 검증 가능성   낮음         높음               높음
  커밋 이력 노출       없음         있음(서버 중심)     있음
  라이선스 안전        높음         높음               높음
  작업량              적음         중간               많음

진행 순서(예정)
 1) [사용자] 원본 GitHub 저장소를 비공개로 전환 (제가 할 수 없는 외부 작업)
 2) 원본 폴더를 통째로 백업 (또는 git clone --mirror)
 3) [Claude] 원본의 "복사본"에서 git filter-repo 로 공개용 이력 생성
      - 포함 경로 / 제외 경로 / 비밀번호 치환 규칙을 먼저 보여주고 승인받은 뒤 실행
      - 후보 포함: Server/, Client/Assets/@Scripts, Client/Assets/Editor 관련, README.md, *.txt 가이드,
                   .gitignore, .gitattributes
      - 후보 제외: @ThirdParty, Lana Studio, Resources/Fonts, AddressableAssets, Prefabs/Scenes 등 에셋
        (에셋 폴더와 @Scripts 의존 관계는 실제로 만들 때 점검)
 4) [Claude] 결과 검증
      - 크기, 커밋 수, 서버 dotnet test 통과 여부, 비밀 문자열(비밀번호 등) 잔존 검사
 5) [사용자] 새 저장소 생성 및 push (push는 사용자가 직접 수행)
