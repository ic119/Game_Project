포션 체력회복 로직 정리
========================

1. 회복 공식
------------
회복량 = Max(1, Round(최대체력 * healPercent / 100))

- 최대체력(maxHp) 대비 healPercent(%) 비율만큼 "현재체력"을 회복시킨다.
- 결과가 0이 되지 않도록 최소 1은 보장한다(비율이 아주 낮아도 무효과로 보이지 않게).
- 회복 후 currentHp는 maxHp를 넘지 않도록 클램프된다.

비율은 ItemData.healPercent 값으로 아이템마다 인스펙터에서 직접 지정한다. 현재 ItemDatabaseSO에
등록된 물약은 아래 1종이며, 몬스터 드랍(DropTables.json, dropRate 0.35)으로 실제 획득 가능하다:
  - potion_hp_small : healPercent = 10  -> 최대체력의 10% 회복

향후 중간/대형 물약(healPercent = 30/50 등)을 추가할 때도 ItemDatabaseSO에 아이템을 새로 등록하고
healPercent 값만 채우면 되며, 코드 변경은 필요 없다.

(데미지 계산의 CombatCalculator.ApplyDefense와 대칭되는 "임시 공식"이다.
 실제 밸런스 기획이 정해지면 CombatCalculator.CalculateHealAmount 한 곳만 수정하면 된다.)


2. 관련 스크립트 구성
----------------------

[1] Assets/@Scripts/Model/Combat/CombatCalculator.cs
    - 전투/회복 수치 계산을 모아두는 순수함수(static) 유틸리티.
    - public static int CalculateHealAmount(int maxHp, int healPercent)
        위 공식을 그대로 구현. 상태를 갖지 않는 순수 계산 함수.
    - 기존 ApplyDefense(int rawDamage, int defense)와 같은 위치/성격의 메서드.

[2] Assets/@Scripts/Model/Combat/HealthComponent.cs
    - 체력/피격/사망/회복을 전담하는 공용 컴포넌트(MonoBehaviour, IDamageable 구현).
    - PlayerCharacterModel뿐 아니라 향후 Enemy 등에도 재사용 가능.
    - public bool Heal(int amount)
        currentHp에 amount를 더하고 [0, maxHp] 범위로 클램프.
        사망 상태(IsDead)이거나 amount <= 0이면 무시하고 false 반환.
        클램프 전후로 currentHp가 실제로 바뀌지 않았다면(예: 이미 만피) 이벤트를 발화하지 않고 false 반환.
        실제로 값이 바뀐 경우에만 OnHealthChanged(currentHp, maxHp) + OnHealed 이벤트를 발화하고 true 반환.
        반환값은 "효과가 있었는가"를 뜻하며, 호출부가 이 값으로 아이템 소모 여부를 판단한다.
    - public bool HealByPercent(int healPercent)
        CombatCalculator.CalculateHealAmount(maxHp, healPercent)로 회복량을 계산해 Heal(amount) 호출, 그 결과를 그대로 반환.
        실제 "포션 사용" 진입점은 이 메서드.
    - 기존 TakeDamage(DamageInfo)와 대칭 구조:
        TakeDamage -> OnDamaged 이벤트 / Heal -> OnHealed 이벤트

[3] Assets/@Scripts/Models/ItemData.cs
    - 아이템 하나의 정적 정의(디자인 데이터, ScriptableObject에 리스트로 등록됨).
    - public int healPercent (Range 0~100)
        itemType이 Potion일 때만 의미가 있는 필드.
        장비 아이템의 bonusAttackPower/bonusDefense와 같은 위치/성격의 "타입별 전용 필드".
        인스펙터에서 물약 아이템마다 원하는 값을 직접 지정(현재 potion_hp_small = 10).

[4] Assets/@Scripts/Model/Character/PlayerCharacterModel.cs
    - 캐릭터의 체력/전투/장비 상태를 총괄하는 퍼사드(HealthComponent, CombatStatComponent, EquipmentController를 들고 있음).
    - public bool UseHealthPotion(ItemData itemData)
        itemData가 null이거나 itemType != Potion이거나 healPercent <= 0이면 무시하고 false 반환.
        healthComponent.HealByPercent(itemData.healPercent)를 호출해 그 결과(true=실제로 회복됨)를 그대로 반환.
        기존 TakeDamage(DamageInfo) -> healthComponent.TakeDamage(...)와 동일한 패스스루 패턴.

[5] Assets/@Scripts/Presenter/Scene/GameSceneManager.cs
    - 인벤토리 UI(UI_InventoryView)의 "사용"(OnUseItemRequested) / "버리기"(OnDropItemRequested) 버튼 클릭을 받아 처리.
    - HandleInventoryUseRequested(UI_InventorySlot _slot)
        1) 슬롯이 장비 슬롯(SlotType != Inventory)이면 -> TryUnequipSlot (기존 로직 그대로)
        2) 일반 인벤토리 슬롯이고 itemType == Potion이면 -> TryUseHealthPotion(itemId, itemData)
        3) 그 외(장비 아이템 등)는 -> TryEquipItem(itemId) (기존 로직 그대로)
    - TryUseHealthPotion(string _itemId, ItemData _itemData)
        1) localInventoryItems에서 해당 itemId의 미장착 스택(InventoryItemStack)을 찾는다.
        2) spawnedPlayerModel.UseHealthPotion(_itemData)를 호출하고, 반환값이 false(효과 없음: 사망 상태/만피/
           healPercent 미설정 등)이면 여기서 즉시 return한다 - 아이템을 소모하지 않고 서버 요청도 보내지 않는다.
        3) 회복에 성공한 경우에만 스택 count를 1 감소시키고, 0 이하가 되면 localInventoryItems에서 제거
           -> RefreshInventoryDisplay()로 UI 갱신.
        4) SaveDataManager.Instance.ConsumeItem(_itemId, ...)으로 서버에 수량 차감을 백그라운드 요청.
    - HandleInventoryDropRequested(UI_InventorySlot _slot) / TryDropItem(string _itemId)
        1) 장비 슬롯(SlotType != Inventory)은 버릴 수 없다(먼저 장착 해제 필요).
        2) localInventoryItems에서 해당 itemId의 미장착 스택 전체(개별 수량이 아니라 슬롯 단위)를 제거 -> RefreshInventoryDisplay().
        3) SaveDataManager.Instance.RemoveItem(_itemId, ...)으로 서버에 아이템 삭제를 백그라운드 요청.
    - 위 두 메서드 모두 TryEquipItem과 동일한 "로컬 낙관적 갱신 + 서버 백그라운드 저장" 패턴을 따른다.

[6] Assets/@Scripts/Modules/SaveDataManager.cs
    - public void ConsumeItem(string _itemId, Action<bool> _onComplete = null)
        POST api/characters/{id}/items/{itemId}/consume 호출(성공 여부만 콜백으로 알림).
    - public void RemoveItem(string _itemId, Action<bool> _onComplete = null)
        DELETE api/characters/{id}/items/{itemId} 호출(성공 여부만 콜백으로 알림).
    - 기존 EquipItem/UnequipItem과 완전히 동일한 "public 진입점 + *AsyncInternal" 구조.

[7] Server/MainServer/MainServer/CharacterServer (서버 프로젝트, CharacterController.cs / CharacterService.cs / ICharacterService.cs)
    - POST /api/characters/{characterId}/items/{itemId}/consume -> CharacterService.ConsumeItemAsync
        해당 itemId의 미장착(EquipSlot == null) CharacterItem을 찾아 Quantity를 1 감소.
        없으면 InvalidOperationException("보유하지 않은 아이템은 사용할 수 없습니다.") -> 400 Bad Request.
        Quantity가 0 이하가 되면 CharacterItems 행 자체를 삭제.
    - DELETE /api/characters/{characterId}/items/{itemId} -> CharacterService.RemoveItemAsync
        해당 itemId의 미장착 CharacterItem을 찾아 행 전체를 삭제. 이미 없으면 에러 없이 현재 상태 그대로 반환(DELETE 멱등성).
    - 두 메서드 모두 EquipItemAsync/UnequipItemAsync와 동일하게 FindOwnedCharacterAsync로 소유자 검증을 거친다.


3. 데이터 흐름 요약
--------------------
[사용]
UI_InventoryView ("사용" 버튼 클릭)
  -> OnUseItemRequested 이벤트
  -> GameSceneManager.HandleInventoryUseRequested
  -> (itemType == Potion) GameSceneManager.TryUseHealthPotion
       -> PlayerCharacterModel.UseHealthPotion(ItemData)  [bool 반환]
            -> HealthComponent.HealByPercent(healPercent)  [bool 반환]
                 -> CombatCalculator.CalculateHealAmount(maxHp, healPercent)
                 -> HealthComponent.Heal(amount) -> currentHp 갱신 시에만 OnHealthChanged/OnHealed 발화, true 반환
       -> 반환값이 false면 여기서 종료(아이템 미소모, 서버 요청 없음)
       -> 반환값이 true면: localInventoryItems 스택 count 감소/제거 -> RefreshInventoryDisplay()
       -> SaveDataManager.ConsumeItem(itemId) -> POST .../items/{itemId}/consume -> CharacterService.ConsumeItemAsync (DB Quantity 감소/삭제)

[버리기]
UI_InventoryView ("버리기" 버튼 클릭)
  -> OnDropItemRequested 이벤트
  -> GameSceneManager.HandleInventoryDropRequested
  -> GameSceneManager.TryDropItem
       -> localInventoryItems 스택 전체 제거 -> RefreshInventoryDisplay()
       -> SaveDataManager.RemoveItem(itemId) -> DELETE .../items/{itemId} -> CharacterService.RemoveItemAsync (DB 행 삭제)


4. 남은 작업 / 제약사항
------------------------
- [해결됨] ItemDatabaseSO의 potion_hp_small에 healPercent=10이 설정되어 실제로 회복이 동작한다.
- [해결됨] Heal/HealByPercent/UseHealthPotion이 bool을 반환하도록 바뀌어, 사망 상태/만피/healPercent 미설정 등
  실제로 회복 효과가 없는 상황에서는 TryUseHealthPotion이 아이템을 소모하지 않고 서버 요청도 보내지 않는다
  (기존에는 효과 유무와 무관하게 항상 소모됐던 버그였다).
- 서버 동기화는 "클라이언트가 로컬 갱신 후 결과를 신경 쓰지 않고 요청만 보내는" 낙관적 방식이다.
  요청이 실패하면 DebugLogManager로 에러 로그만 남기고 로컬 상태를 롤백하지 않는다(기존 EquipItem/UnequipItem과 동일한 한계).
  네트워크 순단 등으로 서버 저장이 실패하면 재접속 시 서버 값(감소 전 수량)으로 되돌아갈 수 있다.
- 서버 측 ConsumeItem/RemoveItem은 EquipItemAsync처럼 itemType(예: Potion 여부)을 검증하지 않는다 - 기존 EquipItemAsync도
  itemType을 재검증하지 않는 동일한 수준의 신뢰 모델이라 새 엔드포인트도 같은 수준으로 맞췄다. GameServer의
  ItemDefinitions.json에는 itemType/healPercent 정보 자체가 없고 MainServer가 GameServer 카탈로그에 접근할 수도
  없어(별도 프로세스), 서버 권위 검증을 추가하려면 아이템 정의를 두 서버가 공유하는 선행 작업이 필요하다.
