================================================================================
 포털 설정 가이드
 (맵 이동 포털 / 좌표 이동 포털 / 닫힌 포털)
================================================================================

 대상 : Client/Assets/AddressableAssets/Prefabs/Object/Maps/Portal.prefab,
        Client/Assets/@Scripts/Controller/Interaction/MapPortalController.cs,
        Client/Assets/@Scripts/Editor/MapDataExporter.cs,
        Server/MainServer/GameServer/MapData/{맵ID}.json


--------------------------------------------------------------------------------
 1. 포털 종류
--------------------------------------------------------------------------------

   종류                 동작                                           서버가 하는 일
   -------------------  ---------------------------------------------  ----------------------------------
   CoordinateTeleport   같은 맵 안의 다른 좌표로 순간이동               이동 속도 검증을 이 순간이동에 한해 예외로 허용
   MapSwap              씬은 유지하고 맵 프리팹만 교체(다른 맵으로 이동)  이동 요청을 검증해 승인/거부하고 방을 옮김

   * 다른 Scene(예: LobbyScene)으로의 전환은 이 컨트롤러의 책임이 아니다.


--------------------------------------------------------------------------------
 2. 맵 이동(MapSwap) 흐름 요약
--------------------------------------------------------------------------------

   1) 플레이어가 포털에 진입(또는 상호작용 키) -> 연출 + 입력 잠금 (지연 0.5초)
   2) 새 맵 프리팹을 먼저 로드하고 검증한다 (이전 맵은 그대로).
        로드 실패 / 시간 초과 / 진입 지점(RespawnPoint) 없음 -> 이전 맵 유지, 실패 안내, 서버에는 아무것도 보내지 않음
   3) 서버에 이동을 요청하고 응답을 기다린다.
        서버 거부(포털 근처 아님, 알 수 없는 맵, 사망 중) -> 이전 맵 유지, 사유 안내
        서버 승인 -> 이전 맵 제거, 새 맵 생성, 서버가 정한 도착 위치/체력으로 맞춤, 새 맵의 플레이어/몬스터 스폰
   4) 맵이 바뀌는 동안(로딩 + 응답 대기)에는 이동/공격/단축키 입력이 잠긴다.

   서버는 아래 조건을 모두 만족할 때만 승인한다 (ClientSession.HandleMapChangeRequest).
     - 사망 중이 아니다.
     - 서버가 아는 마지막 위치가 "요청한 맵으로 가는 MapSwap 포털"의 반경 + 2m 안이다.
     - 도착 맵 데이터(MapData/{도착 맵}.json)가 있다.
   도착 위치는 클라이언트가 보낸 좌표가 아니라 맵 데이터의 도착 지점으로 서버가 정한다.


--------------------------------------------------------------------------------
 3. 닫힌 포털 (도착 맵이 아직 준비되지 않았을 때)
--------------------------------------------------------------------------------

 MapPortalController의 Is Open을 끄면 "닫힌 포털"이 된다.

   - 클라이언트 : 진입해도 이동하지 않고 안내 문구(Closed Message)만 보여준다.
                  이동 연출, 입력 잠금, 서버 요청이 전혀 일어나지 않는다. 쿨다운 동안은 안내가 반복되지 않는다.
   - 내보내기   : 닫힌 포털은 서버 맵 데이터(portals)에서 제외된다. 이게 중요한 이유 -
                  도착 맵 프리팹이 없는 MapSwap 포털이 데이터에 들어가면 그 맵의 "전체" 데이터(상자 등)
                  내보내기가 중단되기 때문이다. 닫아 두면 도착 맵이 없어도 이 맵을 정상적으로 내보낼 수 있다.
   - 서버       : 닫힌 포털은 서버에 존재하지 않는다(요청이 올 일도 없다).

 Portal.prefab은 현재 "닫힌 MapSwap 템플릿"이다 (도착 맵 지정 안 됨, Is Open 꺼짐, "준비 중인 지역입니다.").
 맵에 끌어다 놓기만 하면 안전하게 배치되고, 도착 맵이 준비되면 아래 4장 순서로 연다.


--------------------------------------------------------------------------------
 4. 도착 맵이 준비되면 포털을 여는 순서
--------------------------------------------------------------------------------

   [도착 맵 준비]
   1) 도착 맵 프리팹을 만든다. 프리팹 파일 이름 = 맵 ID = Addressable 주소 = AddressableAssetKey 이름이어야 한다.
   2) 도착 맵 안에 진입 지점 오브젝트(기본 이름 "RespawnPoint")를 둔다.
   3) AddressableAssetKey enum에 새 맵 키를 추가한다(끝에 사용하지 않은 번호로 - 기존 번호 변경/재사용 금지).
   4) 프리팹을 Addressables에 등록한다. 씬에서 로드되는 방식에 맞춰 필요하면 GameScene preload 목록은 넣지 않아도 된다
      (맵 이동 때 로드한다).
   5) 서버가 쓰는 데이터를 내보낸다.
        - Tools/Map/Export Map Data From Selected Prefab  (도착 맵 프리팹을 선택한 상태로)
        - Tools/Monster/Export Spawn Points From Selected Prefab  (몬스터를 둔 맵이면)

   [포털 설정]
   6) 출발 맵의 포털에서 Teleport Type = MapSwap, Target Map Key = 도착 맵, Target Map Entry Point Name = 진입 지점 이름.
   7) Is Open을 켠다.
   8) 출발 맵을 다시 내보낸다 (Export Map Data). 도착 맵 데이터를 먼저 내보냈는지 확인한다.
   9) GameServer를 재시작한다 (맵 데이터는 부팅 시 한 번만 읽는다).

   [내보내기 도구가 잡아 주는 실수]
     - 열린 포털인데 도착 맵(Target Map Key)이 None  -> 오류로 내보내기 중단
     - 열린 포털인데 도착 맵 프리팹이 없음          -> 오류로 내보내기 중단 ("도착 맵이 준비되지 않았다면 Is Open을 끄세요")
     - 도착 맵에 진입 지점이 없음                   -> 오류로 내보내기 중단
     - Teleport Type이 정의되지 않은 값(옛 프리팹)    -> 오류로 내보내기 중단 (예외로 죽지 않는다)
   [서버 부팅 시 경고]
     - 도착 맵 데이터(MapData/{도착 맵}.json)가 없는 MapSwap 포털이 있으면 부팅은 되지만 경고를 출력한다.
       이 포털로의 이동 요청은 UnknownMap으로 거부된다.
       (맵을 하나씩 내보내므로 순서에 따라 일시적으로 생길 수 있다.)


--------------------------------------------------------------------------------
 5. 좌표 이동(CoordinateTeleport) 포털
--------------------------------------------------------------------------------

   - 목적지는 Target Destination(Transform)이 있으면 그 위치, 없으면 Target Coordinate(고정 월드 좌표)다.
   - 내보내기 때 목적지를 서버 데이터에 담는다. 서버는 "포털 범위 안에서 목적지 2m 안으로 이동"하는 요청만
     순간이동으로 인정해 이동 속도 검증을 건너뛴다. 실행 중 SetTargetDestination으로 바꾼 목적지는 서버가 몰라 거부될 수 있다.
   - 같은 맵 안의 이동이라 도착 맵 문제가 없다. 다만 위 3장의 닫힌 포털로도 쓸 수 있다.


--------------------------------------------------------------------------------
 6. 점검 체크리스트
--------------------------------------------------------------------------------

   [ ] 포털 프리팹의 Teleport Type이 CoordinateTeleport 또는 MapSwap으로 올바르게 보이는가
       (옛 프리팹은 폐기된 번호가 남아 있으면 비어 보일 수 있다 - 시작 시 오류 로그가 난다)
   [ ] 열린 MapSwap 포털의 Target Map Key / Entry Point Name이 맞는가
   [ ] 포털 콜라이더 반경이 적당한가 (서버가 이 반경 + 2m를 승인 범위로 쓴다)
   [ ] 출발 맵과 도착 맵 모두 맵 데이터를 내보냈는가
   [ ] GameServer를 재시작했는가
   [ ] 서버와 클라이언트가 같은 프로토콜 버전인가 (맵 이동 승인/거부 응답을 쓰는 버전)


--------------------------------------------------------------------------------
 7. 알려진 한계
--------------------------------------------------------------------------------

   - 승인을 기다리는 동안(왕복 시간) 이전 맵이 그대로 유지되므로 몬스터는 그동안 공격할 수 있다(입력은 잠겨 있다).
   - 응답이 15초 넘게 없으면 이동을 취소하고 안내한다. 이후 늦은 승인이 도착하면 서버 기준으로 맵을 교체해 따라간다.
   - 현재 프로젝트에는 맵 프리팹이 Floor001 하나뿐이고 서버 맵 데이터의 portals가 비어 있어 실제로 열린 포털이 없다.
